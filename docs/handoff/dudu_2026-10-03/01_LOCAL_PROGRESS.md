## 4. 이어서 작업할 순서

1. [원본 2D와 새 3D 참고](02_DUDU_3D_TARGET.md)를 나란히 놓고 최종 캐릭터의 정면·45도·측면·후면 기준을 정한다. 제공 예정인 측·후면 원화가 오기 전에는 그 면을 ‘원본과 동일’하다고 확정하지 않는다. 대구대 엠블럼의 3D 변환·공개 전시 권한을 확인한다.
2. 음성 이름/차례 오류를 실제 마이크에서 재현하고 계약 변경 범위와 회귀 계획을 확정한다. 화면 표시 치환만으로 음성 이름이 통일됐다고 주장하지 않는다.
3. 치료사 승인 스킬 1개를 수직 흐름으로 만든다: 치료사 관찰·명시적 승인 → 서버 권한 → 아동 선택 → 같은 몬스터에서 다른 공격. 기본 공격은 언제나 필수 구간을 통과할 수 있다. 승인 자체를 AI나 라운드 점수에 맡기지 않는다.
4. 재료 1종·물건 1개·서버 재개를 붙여 `발화→참여 보상→제작→다음 회기`를 실제로 이어 준다. 구현되지 않은 부분은 포스터와 영상에서 시안으로 남긴다.
5. 화면/음성/모바일/권한/중복 보상/포스터 캡션을 다시 검증하고, 팀명 등 빈칸과 영상 QR을 확정해 새 화면으로 최종 촬영한다.

## 5. 계약 변경 전 확인

`docs/audit/FROZEN_CORE_CONTRACT.md`는 `backend/app/models.py`, 인증·소유권·치료사 계획·대화/음성 계약, `src/child` 음성 로직 등의 변경 전 사용자에게 **변경 파일·이유·계약 영향·회귀 명령**을 보여 주고 승인을 받으라고 한다. 사용자는 스킬 1개의 실제 작동을 제품 목표로 선택했지만, 위 동결 파일의 구체적 수정 계약은 아직 별도로 확인해야 한다. [1주일 문서의 변경 표](03_WEEK_SCOPE.md#동결-계약git-충돌-검토)를 승인 검토의 출발점으로 사용한다.

회귀 명령은 저장소 계약에 적힌 `npm.cmd test`, `npm.cmd run typecheck`, `npm.cmd run build`, `backend\.venv\Scripts\python.exe -m pytest backend -q`, API 스모크, `git diff --check`, `npm.cmd audit`다. 이번 PC에서는 기존 가상환경 실행기 경로가 깨져 번들 Python에 설치된 패키지 경로를 지정했고, 테스트 임시 폴더도 작업 트리 안에 분리했다. **다른 기기에서는 새 가상환경을 설치해 표준 명령으로 다시 검사한다.**
