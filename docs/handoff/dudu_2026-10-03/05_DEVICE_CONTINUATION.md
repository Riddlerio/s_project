원래 코드의 기준 검사는 프런트 94개, 백엔드 306개가 통과했다. 프런트 타입 검사·배포 빌드·DEMO API smoke·의존성 감사도 통과했다. 백엔드 임시 검사 폴더의 상위 경로가 없어서 발생한 첫 실행 실패는 경로를 준비하고 재실행해 해소했다.

## 사용자가 확정한 범위

1. 기능 오류부터 수정한다. 현재 `Hoya3D.tsx`는 **2.5D 시제품**이다. 최종 3D 모델 제작은 측·후면 원화와 모델 파일을 받은 뒤 진행한다. 원래 정면 도안은 정체성 기준, 목표 이미지의 둥근 조형·털/천 재질은 제작 목표다. 측·후면은 계속 임시 설계로 표시한다.
2. 기존 4개 활동과 각 5라운드, 치료사의 임상 결정권, 기본 공격만으로 클리어하는 경로를 유지한다.
3. 이번 데모는 초밥 하나만 만든다. 빛의 마법에는 벼 수확 장면을 붙여 밥을, 몬스터 모험에는 해변 낚시 장면을 붙여 참치를 모은다. 해당 장면의 2·4라운드 완료 때 재료 1개씩 지급한다. 하늘 오르기·대화 활동은 음식 재료를 주지 않는다. 새 목표 단어나 치료 과제를 추가하지 않는다.
4. 밥 1개 + 참치 1개를 소비하여 참치초밥 1개를 만든다. 옷·연어·추가 레시피는 이번 범위에 넣지 않는다. 재료 양은 별 개수와 분리한다.
5. 라운드의 `success / (success + retry)`가 70% 이상이면 3별 “역시 최고야!”, 50% 이상이면 2별 “정말 잘했어!”, 미만이면 1별 “조금만 더 노력해보자!”를 쓴다. `uncertain`·`no_speech`는 분모에서 제외하고 평가 가능한 시도가 없으면 참여별 1개, 비율은 null이다. 첫 성공에서 라운드가 종료되는 규칙을 유지하므로 1회 성공만으로 3별이 나올 수 있다. 별을 발음 정확도나 치료 효과로 표시하지 않는다.
6. 한 기기만 진행하고, 새 기기에서는 명시적으로 이어받는다. 이어받은 뒤 이전 기기의 제출을 서버가 거부한다.
7. 실제 마이크 검수는 완료 조건이지만, 현재 사용자는 휴대폰 원격 응답만 가능하다고 답했다. 성인의 실제 발화·스피커 청취는 이후 진행한다. 자동 검사와 마이크 화면 진입만으로 실물 검수를 완료했다고 표시하지 않는다.

## 동결 계약 승인과 구현 순서

사용자는 변경 파일·이유·계약 영향·회귀 명령을 확인한 뒤 다음 수정 범위를 각각 승인했다.

- **P0 음성:** `ActivitySession`, `HoyaChat`, `hoyaChatController`, `PlaySession`, 캐릭터 음성, 새 `koreanTts`, 두두 대체 문구, DEMO 대화 제공자와 프롬프트. 이름을 두두로 통일하고 TTS 예약부터 종료·취소·오류 및 300ms 잔향 대기까지 입력을 차단한다. 내부 hoya API/DB 식별자, 아동 원문과 임상 목표는 바꾸지 않는다.
- **S1 치료사 스킬:** 새 SkillGrant 표·adventure API, `main.py` 몬스터 공격 권한 검사, 선택적 공격 필드, 치료사 ChildDetail 패널, 아동 선택. 치료사가 관찰 근거를 선택하고 명시적으로 승인·철회한다. 점수·AI·게임 완료는 영구 스킬을 승인하지 않는다.
- **S2 이어하기와 제작:** 새 ActivityLease·EpisodeProgress·RoundMaterialReward·CraftEvent 표, 활동의 진행 권한·종료·동시 요청 보호, session_state 검증, adventure API, 지도·활동·홈·보상 화면. 기존 표·열 이름을 변경하지 않고 기존 행을 유지한다.
- **별 피드백:** `main.py`의 ROUND_CLEAR, 새 `games/round_rewards.py`, 활동 화면의 표시·음성. 기존 분석과 라운드 종료 규칙을 유지하고 사용자에게 승인받은 칭찬 문구만 사용한다.

회귀 명령은 동결 계약의 백엔드 전체 pytest, 프런트 test/typecheck/build, DEMO API smoke, diff 검사, npm audit다. 권한·소유권·CSRF, 기본 공격, 두 브라우저의 이어받기, 중단 시간 제외, 재료·제작 재시도 및 동시 요청도 따로 확인한다.

## 실제 구현과 검사 상태

이번 작업 브랜치에서 다음을 실제 코드에 연결했다. 두두 호칭·TTS/마이크 교대 게이트, 치료사 매직빔 승인·철회와 서버 권한 검사, 세션별 진행 권한·명시적 이어받기, 라운드별 참여별, 벼 수확/해변 낚시 재료 지급, 참치초밥 제작이다. 제작과 별은 임상 기록의 점수·목표나 치료사 판단을 바꾸지 않는다. 기존 `hoya` API/DB 식별자는 호환을 위해 유지한다. 최종 3D 모델은 여전히 없다.
