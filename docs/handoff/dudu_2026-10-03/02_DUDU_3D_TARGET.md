# 두두 3D 제작 기준 · 현재 시제품과 목표 이미지의 차이

> 결론: 현재 `src/tiger/Hoya3D.tsx`는 17개 게임 상태를 받아 움직이는 **절차형 2.5D 시제품**이다. 정면 도형을 얕게 압출하고 눈·무늬·표정을 앞면에 붙였다. 아래 이미지처럼 털과 천의 질감이 있는 둥근 완전 입체 모델은 **아직 제작되지 않았다.** 새 이미지들은 다음 제작 목표이자 검수 기준이다.

## 참고 이미지의 우선순위

| 파일 | 사용할 부분 | 해석할 때 주의할 부분 |
|---|---|---|
| [원래 두두 2D 정면](references/original_dudu_2d.jpg) | 백호라는 정체성, 얼굴/줄무늬 배치, 흰 몸, 청록 스카프, 청록 겉·연두 안 망토, 원형 가슴 흉장 | 정면 한 장만 있으므로 측·후면 형상은 확정 자료가 아님 |
| [3D 전신 목표](references/dudu_3d_target_front.png) | 큰 둥근 머리·짧고 폭신한 몸·발·꼬리, 털/천/눈 재질, 정면 비례와 중립 포즈 | 생성 이미지의 흉장 문자는 왜곡될 수 있음. 대학 공식 도안과 사용 권한을 별도 확인 |
| [3D 표정·동작 목표](references/dudu_3d_target_poses.png) | 가까이서 보이는 눈·코·귀·입, 손바닥 젤리, 손 흔들기/한 발 들기, 망토와 꼬리의 움직임 | 두 개체가 나와도 제품 캐릭터가 둘이라는 뜻이 아님 |
| [홈 분위기 시안](references/dudu_home_concept.png) | 큰 두두를 중심에 두는 홈 구성, 밝은 하늘/섬, 인사 포즈, 대화 진입의 환영감 | 이미지의 작은 글자·수치·버튼·개인정보·임상 지표는 요구사항이 아님. 아동 앱과 치료사 화면의 기존 정보 구조를 검토하며 적용 |

**충돌 시 원래 2D 도안의 캐릭터 정체성을 먼저 지킨다.** 새 생성 이미지의 봉제 인형 같은 조형·재질·표정은 그 정체성을 3D로 높이는 시각 목표다. 사용자에게서 측면·뒷면 도안이 추가로 오면 그 자료로 보이지 않는 면을 확정한다. 현재 시제품의 평면형 얼굴이나 흉장 근사 표현을 최종 디자인 기준으로 삼지 않는다.

## 지금 화면과 목표의 분명한 차이

| 항목 | 현재 코드/실행 화면 | 최종 목표 |
|---|---|---|
| 조형 | 정면 Shape/압출과 뒤쪽 부피를 조합한 판형 인상 | 정면·45도·측면·후면에서 둥근 머리·주둥이·몸·팔·다리·꼬리가 끊김 없는 3D |
| 표면 | 흰색 기본 면과 평면 검은 줄무늬·외곽선 | 짧고 부드러운 흰 털, 회흑 줄무늬가 곡면을 따라 이어지는 UV/표면 디테일 |
| 얼굴 | 앞면에 놓은 눈·코·입 형태 | 유광 눈과 작은 하이라이트, 입체 회색 코, 부드러운 미소·필요시 열린 입/분홍 입안, 분홍 귀 안쪽 |
| 손·발·꼬리 | 단순 파츠·제한된 포즈 | 둥근 발가락, 검은/회색 발바닥 젤리, 손 흔들 때 보이는 손바닥, 줄무늬가 이어지는 통통한 꼬리 |
| 옷 | 스카프와 망토의 간단한 형상·회전 | 매듭이 읽히는 스카프, 청록 겉면/연두 안감의 양면 망토, 관절·바람·착지에 따라 자연스러운 흐름 |
| 흉장 | 코드로 그린 원형 근사 이미지 | 확인된 공식 엠블럼의 정확한 형태·비례·허용된 표기 |
| 동작 | 상태 신호에 따라 파츠 회전·입 크기 변경 | 리그·표정·꼬리·망토가 결합된 자연스러운 동작과 부드러운 전환 |
| 빛/접지 | WebGL 광원은 있으나 털/천/접지 표현이 부족 | 눈/코의 절제된 반사, 부드러운 조명, 바닥 접지 그림자, 장면과 통일되는 색 |

[현재 실제 아동 홈](screenshots/actual_dudu_home.png)과 [현재 실제 몬스터 게임](screenshots/actual_dudu_monster.png)을 목표 그림과 나란히 비교한다. 현재 캐릭터가 돌아가고 움직인다는 것과 목표 그림 같은 3D 품질을 달성했다는 것은 별개다.

## 제작·저장·연결 방향

1. **편집 가능한 원본 모델을 먼저 확보한다.** Blender 등의 `.blend` 원본, 텍스처 소스, 웹용 `.glb`/`.gltf`와 압축 텍스처를 버전 관리 가능한 경로에 두고, 다른 기기에서 재생성/수정할 수 있게 한다. 이번 브랜치에는 그런 모델 파일이 없다. 생성 이미지 한 장을 평면 카드로 세워 3D 완성으로 취급하지 않는다.
2. **원래 2D의 위치 관계를 모델 시트로 옮긴다.** 정면 무늬와 얼굴 비율을 맞춘 후 곡면에 줄무늬를 놓고, 측·후면은 사용자가 제공할 도안을 받아 확정한다. 도안 전 단계의 측·후면은 임시임을 파일과 검토 화면에 표시한다.
3. **재질을 분리한다.** 털은 저사양 기기에서도 무리 없는 짧은 질감으로, 스카프/망토는 천으로, 눈·코는 부드러운 광택으로 표현한다. 실제 모피 시뮬레이션이 성능을 해치면 노멀/알베도 텍스처로 같은 인상을 만든다.
4. **리그를 화면 동작에 연결한다.** 머리·턱/입·귀·팔·다리·손·꼬리·망토의 기준 뼈와 표정 채널을 만들고, 기존 `<Hoya3D action className>` 및 `HoyaAction` 17개 값을 유지하는 로더/애니메이션 매핑을 설계한다. 로더·새 의존성 추가는 `docs/audit/FROZEN_CORE_CONTRACT.md`의 승인 조건을 먼저 확인한다.
5. **단계별 구현을 정직하게 표기한다.** 1주 시연에는 `IDLE` 숨쉬기/눈깜빡임, `LISTENING`, `TALKING`, `WAVE`, `WALK_TO`, `ATTACK`/`BEAM`의 대표 액션을 고품질로 먼저 검수하고, 나머지 기존 액션 값은 자연스러운 안전 동작으로 처리한다. 제품 완성 기준은 17개 모두의 자연스러운 관절·표정·망토/꼬리 반응이다.

## 최종 육안 인수 조건

- 원화와 목표 3D를 **정면·45도·측면·후면**에 놓고 머리/몸 비율·줄무늬·귀·코·눈·망토·꼬리를 비교한다. 판형 얼굴, 검은 굵은 평면 외곽선, 떠 있는 파츠, 텍스처 끊김, 관절 관통이 눈에 띄지 않는다.
- 홈에서는 인사하는 두두가 충분히 크게 보이고, 게임과 대화에서는 발화 상태에 맞게 듣기/말하기/기다리기가 보인다. 손 흔들기에는 손바닥 디테일, 걷기에는 발 접지, 점프/착지에는 꼬리·망토의 지연 반응이 있다.
- `HoyaAction` 17개(`IDLE`, `LISTENING`, `TALKING`, `CHARGE`, `BEAM`, `RELEASE`, `FLY`, `LAND`, `CAST`, `ATTACK`, `WALK_TO`, `PICK_UP`, `PUT_IN_BAG`, `WAVE`, `CHEER`, `ENCOURAGE`, `THINKING`)를 강제로 하나씩 실행해 표정·관절·프레이밍과 전환을 기록한다.
- 데스크톱/모바일에서 몸과 망토가 잘리지 않고 장면의 텍스트·버튼을 가리지 않는다. 저사양/ WebGL 실패 시에도 원래 백호임을 알아보는 대체 이미지와 같은 치료 흐름을 제공한다. 2026-10-03 작업에서 대체 화면의 캐릭터 호칭은 두두로 바꿨다. 실제 저사양·WebGL 실패 기기에서의 수동 검수는 남아 있다.
- 웹용 모델의 로딩·메모리·프레임을 실제 목표 기기에서 측정한다. 숫자 예산은 대상 기기와 품질 선택이 정해진 뒤 기록하며, 측정 없이 ‘최적화 완료’라고 쓰지 않는다.
- 원본/생성 참고 이미지와 엠블럼의 사용 범위를 확인하고, 공개 영상·포스터·저장소에 사용하는 에셋의 권리를 기록한다.
