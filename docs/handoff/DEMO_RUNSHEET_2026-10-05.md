## 1. 시연 전 점검 (약 10분)

- **기기와 브라우저:** 아이 화면은 아이폰 Safari로 한다. 노트북이 서버를 띄우고, 아이폰은 `https://<노트북 IP>:5183/play`로 접속한다(4절). 치료사 화면은 노트북 Edge 최신판으로 연다. 노트북만으로 할 때도 Edge 최신판을 쓴다.
- **두두 목소리:** 게임·마무리·첫 인사와 DEMO 대화(서버 DEMO 대본)는 VOLI '하람' 소년 음성 파일로 말한다([DUDU_VOICE_VOLI_2026-10-05.md](DUDU_VOICE_VOLI_2026-10-05.md)).
  - 파일이 없는 말(외부 LLM 대화, 치료사가 바꾼 낱말 목록의 일부 문장)은 브라우저 음성으로 말한다.
  - 브라우저 음성은 Edge 온라인 남성 음성(InJoon → Hyunsu)이고 인터넷이 필요하다. 아이폰에서는 기본 한국어 음성으로 나온다. DEMO 대화·게임·마무리는 모두 녹음 파일이라 시연 흐름에서는 거의 쓰이지 않는다.
  - 화면 아래의 VOLI 출처 문구는 무료 플랜 조건이므로 지우지 않는다.
- **마이크:** 주소창 자물쇠에서 마이크를 허용한다. 입과 마이크 사이는 20~30cm, 조용한 곳에서 한다.
- **소리:** 두두가 말할 때는 마이크가 쉬지만, 스피커를 너무 크게 하면 효과음이 다음 말에 섞일 수 있다. 중간 음량으로 맞춘다.
- **점검 화면:** `/voice-mic-check.html`에서 두두 목소리를 고르고, '사' 5번·'스' 5번을 말해 본다. '결과 복사' 값은 판정 기준을 맞출 때 쓴다.
- **시연 계정(리허설 DB 전용):** 아동 `DEMO-CROSSING` / 치료사 `demo-showcase`, 비밀번호는 둘 다 `speechhero`다. 아동 별명은 '두두친구'로, 두두가 "두두친구야", "역시 두두친구야!"라고 부른다.
- **리허설 DB 만들기와 오늘 기록 지우기:** `SEED_DEMO_DATA=true`인 상태에서 아래를 실행한다. 실제 DB에는 실행을 거부한다.
  ```powershell
  backend\.venv\Scripts\python.exe backend\scripts\demo_rehearsal.py provision --database C:\speechhero\rehearsal.db    # 처음 한 번(저장소 밖 경로)
  backend\.venv\Scripts\python.exe backend\scripts\demo_rehearsal.py reset-today --include-mic --database C:\speechhero\rehearsal.db   # 리허설 사이마다(마이크 회기 포함)
  ```
  서버는 `DATABASE_URL=sqlite:///<같은 경로>.db`, `SEED_DEMO_DATA=true`로 띄운다. 초기화 전에는 진행 중인 리허설을 멈춘다.
  `--include-mic`이 없으면 DEMO 모드(누르고 말하기) 회기만 지운다. 시연은 마이크로 하므로 붙인다. 시연 전용 샘플 아동의 오늘 기록만 지우며, 임상 검증한 기록이 있으면 거부한다.

## 3. 문제가 생기면

| 증상 | 바로 할 일 |
|---|---|
| 마이크로 말해도 잘 못 알아듣는다 | 게임을 `DEMO로 시작(누르고 말하기)`로 다시 시작해 버튼(또는 스페이스)을 누른 채 말한다. 화면에 'DEMO 연습'이 표시되는 것이 정상이다 |
| "서버에 아직 대구대 건너기가 준비되지 않았어요" | 서버가 Codex 데모 버전이 아니다. 서버 버전을 확인한다 |
| 두두 목소리가 안 나오거나 기계음이다 | 녹음 파일 재생이 막혔다. 아이폰 무음 스위치·음량을 확인하고 화면의 버튼을 한 번 누른다(누를 때 소리를 깨운다). 파일이 없는 말(외부 LLM 대화 등)만 기계음이 정상이다. 노트북이면 Edge인지·인터넷이 되는지 확인한다 |
| 3D 두두 대신 그림이 보인다 | 그래픽 가속이 꺼져 있다(대체 그림은 정상 동작). Edge 설정 → 시스템 및 성능 → '가능한 경우 그래픽 가속 사용'을 켠다 |
| 휴대폰에서 마이크가 안 켜진다 | 주소가 `https://`인지 확인한다(아래 4절) |

## 4. 휴대폰 검사 (임시)

- 휴대폰 마이크는 `https://` 주소에서만 켜진다. PC에서 `node scripts/serve-phone.mjs <인증서 폴더>`로 임시 HTTPS 서버(자체 서명 인증서, 포트 5183)를 띄운다. 인증서 만드는 법은 [앞으로 할 일](../NEXT_STEPS.md) 2-4절에 있다. 인증서는 저장소에 넣지 않는다.
- PC와 휴대폰을 **같은 와이파이**에 연결하고 `https://<PC의 IP>:5183/voice-mic-check.html`, `https://<PC의 IP>:5183/play`를 연다.
- 처음에 "안전하지 않음" 경고가 나온다. Chrome은 `고급 → 계속`, Safari는 `이 웹사이트 방문`을 누른다.
- PC에 Windows 방화벽 창이 뜨면 **개인 네트워크만** 허용한다. 검사가 끝나면 서버를 끈다.
- 휴대폰에는 Edge 남성 음성이 없을 수 있어 기본 한국어 음성으로 나온다.

## 5. 리허설 확인 목록 (사용자가 "리허설 할게"라고 할 때)

자동 검사로는 확인할 수 없어 남겨 둔 것이다. 출처는 2026-10-05까지의 인계 문서다([작업 기록](../WORK_HISTORY.md) 4절).

**소리와 기기**
- 실제 방에서 '똑' 박 소리와 '네 차례' 차임이 마이크에 아이 말로 잡히지 않는지 확인한다.
- 블루투스 스피커의 출력 지연을 확인한다. 아이폰에서 '똑'과 차임이 나는지 본다(누를 때 효과음 오디오를 깨운다, `unlockFx`).
- 두두가 4박에 부르는 "사!"가 귀로 박에 맞게 들리는지 확인한다(음성 파일 재생 지연은 0.04초로 가정했다).
- 아이폰에서 첫 화면 끊김, 프레임률, 둥근 글꼴 로딩을 본다.

**아이 반응**
- 4~5세가 84BPM과 '넷째 박에 말하기' 규칙을 따라오는지, '딱 맞았어!' 범위(앞 0.3초~뒤 0.4초)가 알맞은지 관찰로 정한다.
- 판정 기준(60ms·80ms·15dB, 2026-10-06 조정)이 아이 목소리와 휴대폰 마이크에서도 맞는지 본다. 3차 측정은 선택이다([측정 기록](MIC_MEASUREMENT_2026-10-05.md)).
- 대화가 자연스러운지 본다. 아이가 대답하는 동안 첫 3번 안에 고르기·빈칸 질문이 없어야 한다. 2026-10-06에 새로 녹음한 질문 7개(예: "시소도 탔어?")가 또렷하게 들리는지 귀로 확인한다.

**치료사 화면**
- 박자 설정이 다음 게임에 반영되는지, 회기 요약에 그 회기의 박자가 나오는지 확인한다.
- 치료사 표현, 기준선, 단서 비교를 사람이 검토한다.

**두두 3D(사람 눈 검수)**
- 스카프 청록의 밝기, 꼬리 위치와 굵기, 표정 선 굵기와 웃는 입 크기, 깜박일 때 눈 둘레의 옅은 타원.
- 물건 줍기와 펀치 동작이 자연스러운지, 흉장 글자('대구대학교', 'DAEGU UNIVERSITY 1956')가 실제 크기에서 읽히는지.

**이번에 하지 않는 것:** 화면 낭독기(VoiceOver·TalkBack) 실사용, 실제 저사양 기기, 치료사 화면 접근성.
