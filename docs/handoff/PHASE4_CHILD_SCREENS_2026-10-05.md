# Phase 4 아동 화면: '네 차례' 신호와 접근성·저사양 점검 (2026-10-05)

> 사용자 승인(2026-10-05): ① '네 차례' 신호 통일, ② 접근성·저사양 점검. 집·지도·보상 화면 재디자인은 리허설 뒤로 미룬다.
> 약속: 마이크 처리 순서는 건드리지 않고, 차임은 마이크가 열리기 전에만 낸다.
> **이후 변경(2026-10-05):** 대구대 건너기는 리듬게임이 되어, 차임 대신 '똑·똑·똑'(마지막 '똑'이 다 들린 뒤 마이크)이 차례 신호다. 나머지 순서(귀 쫑긋 → 소리 → 빛·배지)는 같다([리듬 기록](RHYTHM_CROSSING_2026-10-05.md)).

## 1. '네 차례' 신호

### 1-1. 순서

1. 두두가 말을 마치거나(대화·게임 4종) 말풍선이 동그라미에 들어오면(대구대 건너기) 두 가지를 한다.
   - 두두 귀가 쫑긋 선다(0.38초).
   - 차임이 울린다. 솔→레 두 음이고 약 0.27초다.
2. 차임이 다 들린 뒤에 듣기를 연다.
   - 기본 0.45초를 기다린다.
   - 기기 출력 지연(블루투스 스피커 등)이 있으면 그만큼 더 기다린다. 최대 1초다.
3. 듣기가 열리면 두 가지가 켜진다.
   - 화면 가장자리의 금빛 테두리.
   - 두두 무대 오른쪽 위의 '🎤 네 차례!' 배지. 읽기 도구(`role="status"`)에도 알린다.
4. 듣는 동안 빛과 배지는 움직이지 않는다(듣는 동안 연출 0). 깜박임과 빨간색은 쓰지 않는다.
   - 움직임 줄이기 설정이면 나타날 때의 효과도 없다.
   - 앱에 배경음이 없어 '배경음 낮춤'은 해당 없다.

빛과 차임을 같이 켜지 않은 이유가 있다. 아이가 빛을 보고 바로 말을 시작하면, 마이크가 열리기 전에 첫소리(/ㅅ/ 마찰)가 잘릴 수 있다.

### 1-2. 화면별 연결

| 화면 | 신호를 내는 때 | 차임 동안 마이크를 막는 방법 |
|---|---|---|
| 두두와 대화하기 | 두두가 답을 마칠 때마다. 대화를 끝내는 답 뒤는 빼고, 다시 말해 달라는 답 뒤는 포함 | 대화 제어기에 선택 단계 `beforeListen`을 더했다. 신호 동안 상태가 `RESPONSE_SPEAKING`이라 마이크 소리를 아이 말로 받지 않는다. 넘기지 않으면 전과 같다 |
| 대구대 건너기 | 말풍선이 동그라미에 들어올 때마다. 두두 시범 뒤도 포함 | 신호가 끝난 뒤에 듣기(`listening`)를 켠다. '딱 맞았어!' 시간도 이때부터 잰다 |
| 게임 4종(빛의 마법·하늘 오르기·몬스터 모험·두두와 소풍) | 새 항목·새 시도 때, 다시 듣기·무발화 뒤에 같은 항목을 다시 들을 때 | 주변 소리 보정(1초)이 끝나도 신호가 끝날 때까지 기존 대기 플래그(`modelPending`)로 마이크 소리를 받지 않는다. 열 때 그 전 소리 조각을 버린다. DEMO 누르고 말하기(버튼·Space)도 '네 차례!' 뒤에만 받는다 |

### 1-3. 바뀌지 않은 것과 바뀐 것

**그대로인 것**
- 마이크 처리 순서(캡처 → 분석 → 인식 → 제출)
- 보정 시간 `CALIBRATION_MS`
- 판정 기준
- 서버 API와 저장 필드

**바뀐 것**
- 듣기 시작이 차임 뒤로 약 0.5초 늦어졌다.
- 게임 4종의 반응 시간(`onsetLatencyMs`)은 이제 듣기가 열린 때('네 차례!')부터 잰다.
  - 전에는 따라 말하기면 두두 시범이 끝난 때, 그 밖이면 항목이 나온 때(보정 1초 포함)부터 쟀다.
  - 이 값은 치료사 화면의 '저장된 측정 요약'에만 보이고, 판정·지표에는 쓰지 않는다.
  - 대화와 건너기는 그대로다.

### 1-4. 두두 귀 쫑긋

- **모델 파일(GLB):** 귀 뼈가 없고 귀가 머리 뼈에 붙어 있다.
  - 듣기(LISTENING)로 바뀌는 순간 머리를 위로 15% 늘였다가 돌린다(0.38초, `src/tiger/duduPerk.ts`).
  - 대화 화면을 연속으로 찍어 보니 귀 끝이 약 20px 올라갔다 돌아왔다.
- **절차형 대체 모델:** 귀를 늘인다.
- **하지 않는 때:** 움직임 줄이기 설정이나 정지 장면.
  - 건너기는 듣는 동안 두두가 멈추는 규칙이 있다. 그래서 쫑긋은 차임 동안 끝나고, 듣기가 열리면 그 자세로 멈춘다.

### 1-5. 시간 측정

헤드리스 Edge로 쟀다. 차임 소리를 내는 순간과 배지가 켜지는 순간을 기록했다. 실제 음성 장면에는 가짜 마이크 파일('사' 반복)을 넣었다.

| 장면 | 듣기 열림 | 차임 → 열림(ms) | 제출 | 듣는 중 차임 | 신호 밖 제출 |
|---|---|---|---|---|---|
| 대화, 실제 음성(로그인 뒤 자동 시작) | 4 | 500~502 | 4 | 0 | 0 |
| 대화 DEMO | 4 | 500~505 | 4 | 0 | 0 |
| 건너기, 실제 음성(서버 판정) | 5 | 499~500 | 5 | 0 | 0 |
| 건너기 DEMO(미리보기, 서버 없음) | 4 | 493~502 | — | 0 | 0 |
| 빛의 마법, 실제 음성 | 11 | 497~501 | 10 | 0 | 0 |
| 하늘 오르기 DEMO | 5 | 496~501 | 4 | 0 | 0 |
| 하늘 오르기·몬스터 모험·두두와 소풍, 실제 음성 | 9·9·10 | 494~510 | 8·8·9 | 0 | 0 |

- 건너기 실제 음성 경로에서 가짜 마이크 '사'는 6/6 성공이었다(전에 같은 검사로 5/6).
- 하늘 오르기 DEMO에서는 '네 차례!' 전에 누르고 말하기가 막혀 있다가 뒤에 열렸다(4/4).
- 저사양: 휴대폰 폭에서 CPU를 4배 느리게 한 결과다.
  - 대화·집·건너기·빛의 마법 모두 초당 60프레임을 유지했다.
  - 차임 → 열림은 498~504ms였다.

## 2. 접근성·저사양 점검

### 2-1. 방법

- **대상:** 아동 화면 9종 × 데스크톱 1280 / 휴대폰 390. 9종은 시작·집·대화·건너기 안내·건너기 진행·마무리·지도·게임·보상이다.
- **axe-core 4.13:** WCAG 2.2 A/AA와 best-practice 규칙으로 검사했다. 임시 폴더에만 설치했고 프로젝트 의존성이 아니다.
- **누르는 크기:** 보이는 버튼·링크·입력·라디오 라벨 중 44×44px보다 작은 것을 찾았다.
- **키보드:** Tab으로 차례대로 이동하며 순서와 초점 표시를 확인했다.
- **움직임 줄이기:** 실행 중인 CSS 애니메이션을 세고, 두두 영역이 1.2초 사이에 몇 픽셀 바뀌는지 쟀다.
- **WebGL 없음:** 브라우저 3D 기능을 끄고 대체 화면·오류·가로 넘침을 확인했다.

### 2-2. 고친 것

| 항목 | 전 | 후 |
|---|---|---|
| 건너기 '누르고 말하기' 버튼 안의 'Space' 글씨 | 대비 1.37:1(초록 위 회색) | 연두, 약 5.7:1 |
| 집 바로가기 번호, 지도 레벨·카드 글씨, 게임 진행 칸 | 3.1~4.48:1 | 기존 토큰 중 진한 색으로 바꿈(4.5:1 이상) |
| '선생님: 게임으로 넘기기' | 높이 28px | 44px |
| 지도 '← 두두의 집', 모험 방법 선택 | 32·34px | 44px |
| 게임 '저장하고 집으로'(휴대폰) | 35px | 44px |
| 두두와 소풍 DEMO 입력 칸 | Space를 누르고 말하기가 가로채 띄어쓰기를 못 함 | 입력 칸에서는 띄어쓰기, 칸 밖에서는 그대로 누르고 말하기 |
| 휴대폰 대화 화면 | '대구대 건너기' 버튼이 0.8px 넘쳐 가로 스크롤이 생김 | 칸 폭에 맞춤 |
| 움직임 줄이기 | 건너기·빛의 마법만 두두가 멈추고, 대화·집·다른 게임은 계속 움직임 | 공통 3D 두두(`Hoya3D`)도 동작마다 한 자세로 멈춤 |

### 2-3. 결과(고친 뒤)

- **axe·누르는 크기·초점 표시:** 18개(9화면 × 2폭) 모두 axe 위반 0건, 44px 미만 0개, 초점 표시 누락 0건이다.
- **Tab 순서:** 화면 위에서 아래 순서와 맞았다.
  - 건너기·게임의 DEMO 화면에서는 Space가 '누르고 말하기'다. 그래서 다른 버튼은 Enter로 누른다(기존 동작이고, 버튼에 'Space'가 적혀 있다).
- **움직임 줄이기:** 대화·집·건너기·하늘 오르기·빛의 마법 모두 실행 중 CSS 애니메이션 0개, 두두 영역 변화 0픽셀이다.
- **WebGL 없음:** 5화면 × 2폭 모두 간단한 두두 그림으로 바뀌었다. 페이지 오류 0건, 가로 넘침 0건이다(고친 뒤).
  - '네 차례!' 배지와 빛은 대체 화면에서도 같은 자리에 나온다.

## 3. 하지 않은 것·남은 확인

- **실제 기기에서 차임 듣기:** 아이폰·안드로이드·블루투스 스피커에서 차임 소리와 출력 지연을 확인하지 않았다. 리허설 때 한다.
  - iOS를 위해 누를 때 효과음 오디오를 깨우게 했다(`unlockFx`). 실기기에서는 확인하지 않았다.
- **차임이 마이크에 들어가는지:** 실제 방에서 차임이 아이 말로 잡히지 않는지 확인하지 않았다. 리허설 때 한다.
  - 헤드리스 검사는 소리를 내보내지 않아서 시간 순서만 확인했다.
- 화면 낭독기(VoiceOver·TalkBack) 실사용, 실제 저사양 기기는 확인하지 않았다.
- 집·지도·보상 재디자인은 리허설 뒤에 한다(사용자 결정).
- 치료사 화면 접근성은 이번 범위 밖이다.
