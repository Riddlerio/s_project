## 2. 원래 아이디어 → 보완 (언어치료 전문성)

### ② 대화

- **보완: 대화를 '유도 대화'로 만든다.** 자유 대화는 가장 어려운 단계(자발 발화)다. 두두가 질문을 설계해 목표 낱말이 나오게 한다.
  - 선택 질문: "사과가 좋아, 수박이 좋아?" (그림 두 장)
  - 빈칸 채우기: "빨갛고 동그란 과일은 사…?"
  - 먼저 들려주기(모델링): "두두는 '사과'를 좋아해. 너도 말해 볼래?"
  - 다시 들려주기(recast): 아이 말을 고치라고 하지 않고 두두가 바르게 한 번 더 말한다("맞아, 사과!").
- **"10번 이행" → "목표 낱말이 들어간 시도 10회".**
  - 자동 판정은 근사이므로 '정확히 10번'이라고 하지 않는다. 대화 근거 값(TARGET_OBSERVED 등)으로 세고, 정확도는 치료사가 확인한다. 이는 동결 규칙이다: TARGET_OBSERVED를 정확한 발음으로 취급하지 않는다.
  - 10회가 되면(최소 2분) 게임 안내로 넘어간다. 5분이 지나면 횟수와 관계없이 넘어간다.
  - 3턴 연속 말이 없으면 그림 선택 질문으로 쉽게 바꾼다. 그래도 어려우면 게임으로 넘어간다. 치료사가 '넘기기'로 넘길 수도 있다.
- 목표 단계에 맞춰 유도 방식을 고른다. 음절 단계 아이는 따라 말하기 위주, 낱말 단계 아이는 선택 질문·빈칸 위주로 한다.

### ④ 대구대 건너기

- **10줄 = 5구간 × 2줄.** 기존 5라운드 기록 구조와 치료사 타임라인(1~5라운드 띠)에 맞춘다. 구간마다 단서를 하나씩 줄인다.

  | 구간(라운드) | 아이가 하는 것 | 단서 | 치료 초점 |
  |---|---|---|---|
  | 1. 두두 따라 건너기 | 같은 음절 반복(사·사) | 두두 시범 + 그림 | 단서에 따른 목표 소리 산출(모방) |
  | 2. 혼자 건너기 | 같은 음절(사·사), 두두 시범 없음 | 글자·그림 | 독립 산출 |
  | 3. 모음 바꿔 건너기 | 모음을 바꿔서(소·시) | 글자·그림 | 모음 환경 바꾸기(무작위 연습) |
  | 4. 낱말 건너기 | 사과·수박 | 그림 | 낱말 수준 산출 |
  | 5. 정문까지 | 음절·낱말 섞어서(수·시소) | 그림 | 혼합 연습, 도착 |

  치료사가 정한 목표 단계에서 시작한다. 낱말 단계 아이는 1~3구간도 낱말로 한다. 시작 전에 시범을 1번 보여 주고, 이 시범은 기록하지 않는다(리듬 세상의 연습 단계를 참고).
- **"정확히 말하면 점프" → "서버 판정이 '성공'이면 점프".** 효과는 서버 결과만 따른다.
  - 데모 목표 소리는 **/ㅅ/**로 한다. 지금 실시간 음향 근사 판정이 있는 소리이기 때문이다(소리 시작에 마찰음이 있는지). 다른 소리는 브라우저 음성 인식에 기대야 해서 음절 단위 판정이 불안정하다. 근사임을 치료사 화면에 표시한다.
  - 성공하면 다음 줄로 점프한다. 칭찬은 "정말 잘했어!", "좋아!", "멋져!"를 돌려 쓴다(같은 말만 반복하면 의미가 줄어든다).
  - 마찰음이 없으면(예: "사" 대신 "다") 두두가 제자리에서 짧은 단서를 준다("바람 소리 '스~'를 먼저!"). 같은 음절을 한 번 더 시도하고, 최대 2번 뒤에는 넘어간다. 실패 연출은 없다.
  - 말이 없거나 판정이 불확실하면 두두가 다시 들려준다. 실패로 표시하지 않는다(원칙).
  - 말하기 구간을 지나쳐도 글자는 띄우지 않는다. 두두가 발을 동동 구르는 웃긴 반응을 보이고 다음 음절로 넘어간다.
- **"처음엔 천천히"의 구체화.**
  - 템포를 극단적으로 늦추지 않는다(4세 아이는 너무 느린 박에 오히려 못 맞춘다). 대신 말할 기회 사이 간격을 길게 둔다.
  - 처음에는 말풍선이 5초 동안 다가오고, 말하기 구간은 4초, 다음 음절까지 쉼이 있다. 1회 약 10초 × 10줄(다시 포함 10~20회)로 약 2~4분이다.
  - 최근 8회 중 서버 판정 성공이 80% 이상이면 간격을 0.5초씩 줄인다. 한 번에 하나만 바꾼다.
  - 2회 연속 어려우면 자동으로 느려진다.
  - 상한은 자연스러운 말속도다(학령전 아동 /퍼/ 반복 규준이 초당 3~4.5회. 이보다 빠르게 하지 않는다).
  - 말더듬·마비말장애 아동은 속도 올리기를 끈다(치료사 설정).
- 장면에 차는 넣지 않는다. 신호등이 초록불인 횡단보도다. 위험 연출을 하지 않는다.

### ⑤ 마무리

- "역시 ○○야"의 이름은 아동 등록 때 정한 별명(현재 `heroName`)을 쓴다. 실명은 저장하지 않는다.
- 아이용 요약은 시도 수만 말한다: "오늘 '사' 소리를 정말 많이 말했어."(두두 음성 파일로 말하려고 횟수 대신 고정 문장, 2026-10-05) 점수·정확도는 아이 화면에 보여 주지 않는다.
- 일반화를 위해 가정 연습 한 가지를 제안한다: "집에서 '사과'라고 말해 볼까?"
- 노력·과정을 칭찬한다: "끝까지 해냈어!"

### 공통 접근성

- 두두가 하는 말은 모두 자막으로 띄운다(청각장애 아동 고려).
- 소리와 그림 단서를 함께 준다. 큰 버튼, 일시정지, 움직임 줄이기를 지원한다.
- 마이크가 안 되면 DEMO(누르고 말하기)로 대신한다. 이는 실제 발음 평가가 아님을 표시한다.

## 5. Codex 설계(PR #10)와 충돌 점검

- **PR #10 상태:** 기준 브랜치는 `claude/dudu-followup`이다. Claude의 최신 커밋(`7967d85`, `3c5c88e`)을 이미 포함했고, GitHub 기준 병합 가능(MERGEABLE) 초안이다.
- **바꾸는 파일:** 치료사 화면(`src/therapist/**`), 새 모듈 `backend/app/therapist_insights/`, `main.py` 3곳(import, `/progress` 삭제, router 등록), `package.json`(recharts 제거), README·ROADMAP.
- **글자 충돌:** 데모 작업은 `src/child/**`, `src/tiger/**`, 새 게임 장면, `backend/app/games/**`, `schemas.py`·`session_state.py`의 게임 목록, `hoya` 데모 대본을 바꾼다. PR #10과 겹치는 파일은 `main.py`뿐이고 다른 줄이다. **PR #10을 먼저 병합하고 그 위에서 작업하면 충돌이 생기지 않는다.** README·ROADMAP은 병합 뒤에 고친다.
- **의미상 맞출 것:**
  1. **새 게임 이름표:** 치료사 화면은 `src/therapist/planning.ts`의 `ACTIVITY_LABELS`로 활동 이름을 보여 준다. '대구대 건너기'를 넣지 않으면 영문 id가 보인다. 치료사 영역이라 Codex가 맡는다.
  2. **빛의 마법 숨김의 일관성:** 치료사 활동 제안(`clinical/activity_recommendation.py`, 마찰음 지속 → 빛의 마법)과 회기 계획 기본 게임(`MAIN_GAME_BY_LEVEL`의 음소 단계, 조정 가능한 heuristic)이 아이 화면에서 숨긴 게임을 추천하지 않게 바꾼다. 치료사 선택 목록(`ActivityRecommendationPanel`)에서도 숨긴다.
  3. **동결 영역:** 회기 계획 schema(`therapist_planning/**`)의 게임 목록은 동결이다. 데모는 계획이 게임을 구동하지 않으므로(Phase 7 미착수) 새 게임을 계획 목록에 넣지 않고 진행한다. 계획에 넣으려면 별도 승인이 필요하다. 한계로 기록한다.
  4. **대화(`hoya/**`) 동결:** 경로·schema·근거 값은 그대로 두고, 시작 문구와 유도 대본(heuristic)만 바꾼다.
  5. **라운드 구조:** 치료사 타임라인은 1~5라운드를 가정한다. 그래서 새 게임도 5라운드로 맞춘다(2절).
- **결론:** 충돌 없이 진행할 수 있다. 순서는 PR #10 병합(사용자 확인) → 데모 작업이다.

## 6. 근거 요약 (조사 2026-10-04~05)

| 주제 | 내용 |
|---|---|
| 리듬·운율 개입 | 말실행증에서는 운율 중심 치료(ReST) RCT 26명에서 조음·운율이 향상되고 일반화됐다([Murray 2015](https://eric.ed.gov/?id=EJ1067902)). DTTC도 느리게 시작해 정확해지면 정상 속도로 올린다. 일반 말소리장애에서 리듬 자체가 정확도를 올린다는 근거는 약하고([van Tellingen 2023](https://pubmed.ncbi.nlm.nih.gov/35900281/)), 이 경우 리듬은 연습량·동기를 높이는 틀이다. |
| 속도와 명료도 | 아동 538명 연구에서 빨리 말할수록 명료도가 떨어졌다([Mahr 2025](https://doi.org/10.1044/2024_jslhr-24-00356)). /퍼터커/ 교대운동속도는 평가 지표이지 연습 목표가 아니다([김재옥 외 2018](https://doi.org/10.12963/csd.17451)). |
| 피드백·연습 | 운동학습 원리상 습득 초기에는 피드백을 자주 주고, 무작위·다양한 연습이 유지에 유리하다([Maas 2008](https://experts.arizona.edu/en/publications/principles-of-motor-learning-in-treatment-of-motor-speech-disorde/)). |
| 리듬 세상 설계 | 미니게임 하나에 규칙 하나, 연습 단계, 소리 단서 우선, 템포·노트 수만으로 난이도를 올리지 않음, 웃기고 부드러운 실패 연출, 3번 실패 시 넘어가기([사장이 묻는다](https://iwataasks.nintendo.com/interviews/wii/rhythmheavenfever/0/0/)). |
| 기능 어휘 | 고빈도 낱말로 치료하면 일반화가 컸다([Morrisette & Gierut 2002](https://pubs.asha.org/doi/10.1044/persp1.SIG1.57)). 핵심 어휘 접근은 비일관적 말소리장애에서 효과적이었다([Crosbie 2005](https://onlinelibrary.wiley.com/doi/abs/10.1080/13682820500126049)). |
| 이름 | 미국 Flint Rehabilitation의 실어증 앱 이름도 **Speech Hero**다(메트로놈 타이밍 판정, [NCT04471935](https://clinicaltrials.gov/study/NCT04471935)). 포스터·공개 전에 확인이 필요하다. |

## 7. 5일 일정과 분담

파일 경계: **Claude**는 `src/child/**`, `src/tiger/**`, `src/game/**`(새 게임 장면), `src/dev/**`, 두두 목소리(`src/speech/duduVoice.ts`, `koreanTts.ts`의 음성 선택)를 맡는다. **Codex**는 `backend/**` 전부(대화 대본·전환 신호, 새 게임 서버, 활동 제안·계획 조정), `src/therapist/**`, 새 API 필드의 `src/api/**` 타입을 맡는다. 같은 파일을 동시에 고치지 않는다.
