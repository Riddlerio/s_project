## 3. Phase 5·7의 구체 목표

### 게임 구성 (Phase 5)
각 게임의 치료 과제와 라운드 파라미터(목표 지속시간, 단서 정책, 성공 규칙)는 그대로 두고 **연출만** 올린다. 레퍼런스의 근거는 조사 문서 C절에 있다.

| 게임 | 원리 | 5라운드 연출 |
|---|---|---|
| 빛의 마법(/ㅅ/ 지속) | 소리를 이어 가는 동안 차오르거나 걷힘 | 아침 논 → 참새 → 해 질 녘 반딧불 → 바람 들판 → 밤 등불 축제 |
| 하늘 오르기(발성 시작·지속·재개) | 소리 내는 동안 열기구 상승, 쉬면 구름 쉼터에 내려앉음(떨어지지 않음) | 들판 → 나무 꼭대기 → 구름 바다 → 무지개 다리 → 별하늘 |
| 몬스터 모험(음절→단어→명명→새 장면→구) | 발화 단위가 커질수록 주문이 화려함. 몬스터는 달래서 친구로 | 게 → 문어 → 그림 카드 섬 → 산호 동굴 → 참치 |
| 두두와 소풍(선택·요청·구·문장·이야기) | 그림 고르기, 숲속 친구의 요청, 바구니 채우기, 사진첩 | 돗자리 → 도시락 → 친구 초대 → 소나기와 무지개 → 노을 사진첩 |

공통 규칙: 볼륨을 보상에 쓰지 않는다. NO_SPEECH·UNCERTAIN은 멈추고 다시 시범을 보인다(실패 연출 없음). 아이가 말하는 동안에는 움직임과 효과음을 쓰지 않는다. 초밥 만들기는 말하기 부담이 없는 쉬는 장면이다.

### 치료사 데이터 (Phase 7)
- **회기 타임라인:** 라운드 띠 위에 시도 하나를 점 하나로, 출처(시스템 측정·자동 추정·치료사 확인)를 모양으로 구분. 점을 누르면 측정값·관찰·확인/수정/거절.
- **목표별 추이:** 기준선과 최근 비교, 단서 단계를 겹쳐 표시. 실제·DEMO·샘플 분리.
- **데이터 품질 표시:** NO_SPEECH·UNCERTAIN·잡음, 분모 제외 표시, 아동 음성 인식의 한계 고지.
- **결정 지원:** 제안마다 근거(입력·규칙·한계)를 펼쳐 보고, 치료사가 고른 뒤에만 반영. 게임 점수(별·빔·높이)는 보이지 않는다.
- **계획 실행:** 승인한 회기 계획(불변 revision)이 아이의 활동·자극어·단서를 정한다. 기존 발화 기록의 당시 목표 버전은 보존한다.
- 원음 청취는 보호자 동의·보존·삭제 설계가 먼저다(장기 목표, 현재 원음 미저장).

## 4. 3D 두두 제작 과정 (선택: AI 생성 후 정리)

**진행(2026-10-04):** 1~2·5~8단계를 Meshy Pro 비공개로 마쳤고 GLB를 앱에 연결했다. 3·4단계의 Blender 다듬기와 9단계 사람 검수는 남았다. 기록은 [3D 제작 자료](../assets/dudu3d/README.md).

**전제 조건(사용자):** ① 대구대학교 권리자의 서면 허락. 생성 서비스 약관상 일반 고객의 입력·출력이 학습에 쓰일 수 있다. ② 유료 플랜의 비공개 모드(무료는 결과가 공개됨). ③ C 드라이브 여유 공간 확보(Blender와 작업 파일에 수 GB). 로컬 생성은 하지 않는다. Hunyuan3D는 라이선스 지역에서 한국이 제외되고, TRELLIS는 16GB GPU가 필요하다.

1. **입력 준비:** 조형 도면을 정면·측면·후면으로 잘라 배경·비율을 맞춘다.
2. **생성:** Meshy 또는 Tripo의 멀티뷰 생성으로 여러 후보를 만들고 4방향을 원화와 비교해 고른다.
3. **정리:** Blender에서 대칭·리메시, 휴대폰용 1~2만 삼각형, UV.
4. **질감:** 줄무늬·털결을 텍스처에 베이크하고 색은 디자인 토큰을 쓴다. 흉장은 확정된 공식 형태로 교체한다.
5. **리그:** 서비스 자동 리깅 후 꼬리 체인·귀·망토 본을 추가한다. 표정은 깜박임 1개와 입 모양 6개(닫힘·아·이·우·오·ㅅ)로 시작한다.
6. **동작:** `HoyaAction` 17개를 클립으로 만든다. idle 위에 '듣기'를 덧입히고, 성공·격려는 한 번 재생 후 idle로 돌아간다.
7. **웹 내보내기:** GLB + meshopt + KTX2(gltf-transform), 목표 휴대폰에서 로딩·프레임 측정.
8. **앱 연결:** GLTFLoader(three 내장, 새 의존성 없음) 도입은 동결 계약상 사용자 승인 후 진행한다. 현재 절차형 모델은 모델 파일이 없거나 로딩에 실패할 때의 대체로 남긴다.
9. **검수:** `/dudu-review.html`에서 4방향·17동작을 원화와 비교하고 사용자 승인.

그동안 절차형 모델(`src/tiger/DuduModel.tsx`)과 흉장 근사 재현(`src/tiger/duduEmblem.ts`)을 계속 다듬는다.
