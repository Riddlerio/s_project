# 실제 마이크 수동 시험

Chrome 또는 Edge와 실제 마이크가 있는 컴퓨터에서 수행한다. 프런트엔드는 `npm.cmd run dev`, 백엔드는 로컬 서버로 실행한다. 개발 서버는 `127.0.0.1:5173`에서 연다. 음성은 브라우저의 Web Speech API 제공업체로 전송될 수 있으므로 시연용 발화만 사용한다.

시험 날짜, 브라우저 버전, 운영체제, 마이크 모델, 주변 소음, 각 항목의 통과/실패와 화면 메시지를 기록한다.

1. [ ] Chrome/Edge에서 사이트의 마이크 권한을 허용한다.
2. [ ] `HERO01`로 입장하고 모험 지도를 연다.
3. [ ] **실제 음성** 모드를 선택해 세션을 시작한다. 지원하지 않는 브라우저에서는 이 선택이 비활성화되는지 확인한다.
4. [ ] 목표 단어가 `사과`일 때 실제로 “사과”를 발화한다. 발성 시작, 인식, 게임 반응을 확인한다.
5. [ ] 성공 또는 재시도 이벤트가 화면과 치료사 세션 상세의 이벤트 로그에 남는지 확인한다.
6. [ ] 발화하지 않고 기다려 no-speech 상태를 확인한다. 이 경우 VAD가 발화 종료를 만들지 않아 자동 제출되지 않을 수 있다. Web Speech API가 `no-speech`를 반환하면 빈 인식 결과로 처리되는지 확인한다.
7. [ ] 새 세션에서 마이크 권한을 거부한다. 오류 메시지와 **DEMO 모드 선택** 경로를 확인하고, 지도에서 DEMO 세션을 시작한다.
8. [ ] Magic Beam에서 “스~~~~”를 지속 발화한다. 빔이 시작·진행·종료 순서로 표시되는지 확인한다.
9. [ ] 같은 목표에서 짧은 발화와 긴 발화를 비교한다. 발성 길이와 성공/재시도 결과의 차이를 기록한다. 최대 발화 시간 8초에서 종료되는지도 확인한다.
10. [ ] 세션을 완료한 뒤 치료사 대시보드에서 새 세션 기록, 발화 기록, 이벤트를 확인한다.

추가 확인: 브라우저의 음성 인식 오류나 네트워크 오류가 발생하면 화면 메시지와 재시도 동작을 기록한다. 녹음 장치가 사라졌다가 다시 연결되었을 때 VAD가 다음 발화를 정상 감지하는지도 확인한다. 현재 코드의 **다시 시도** 버튼은 오류 표시만 지우므로, 장치나 권한을 복구한 뒤에는 새 세션을 시작해야 할 수 있다.

## 코드 점검 결과

- Web Speech API를 지원하지 않으면 지도에서 실제 음성 선택이 비활성화된다. 실제 모드에서 인식기 생성에 실패해도 오류가 표시되며 DEMO 모드 선택 경로가 있다.
- 마이크 권한 거부는 `getUserMedia` 실패로 화면에 전달된다. 오류 문구는 브라우저 예외에 따라 다르다.
- 인식기의 `no-speech`와 종료 이벤트는 빈 문장으로 처리한다. 다른 인식 오류는 Promise 거부로 처리하며, 발화 종료 뒤 제출 단계에서 화면에 표시된다. 인식 시작 예외나 발화 종료 전 오류의 화면 처리는 추가 수동 확인이 필요하다. 인식 중지 후 결과가 없으면 3초 뒤 빈 문장으로 처리한다.
- VAD는 발화 종료 또는 최대 8초가 지나면 `VOICE_END`를 만든다. 세션 항목이 바뀌거나 캡처 효과가 다시 시작되면 새 VAD를 만들므로 상태가 초기화된다. 무음 상태에서 자동으로 시도를 제출하는 별도 타이머는 없다.
- Magic Beam은 `VOICE_START` → `VOICE_CONTINUE` → `VOICE_END` → 서버 결과 순서로 진행한다. 실제 마이크의 발성 길이와 게임 결과의 일치는 수동 시험이 필요하다.
